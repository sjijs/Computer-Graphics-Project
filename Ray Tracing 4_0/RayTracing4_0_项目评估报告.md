# Ray Tracing 4.0 项目评估报告（CPU路线）

评估对象：`Ray Tracing 3_1` 代码基线  
评估日期：2026-03-21  
角色视角：图形学光线追踪渲染器技术架构师

---

## 0. 执行摘要

当前项目已具备“教学级/入门研究级”路径追踪器的核心能力：BVH、多材质、体积介质、环境贴图、多线程分块、渐进显示。  
如果目标升级为“高拟真、可稳定产出精美真实画面的 CPU 渲染器（暂不考虑 CUDA）”，结论是：

1. 可以接入 Disney BRDF，但现有积分器接口不够，需要先做一次渲染方程层面的接口升级。  
2. 外部模型几何已可导入渲染，但“外部模型贴图与材质链路”目前只实现了很小一部分，离完整 PBR 资产支持还有明显距离。  
3. 距离目标状态仍有较大工程差距，核心缺口集中在：`BSDF/PDF/MIS` 体系、灯光采样、资产系统、色彩与后处理、采样收敛效率与验证体系。

建议将 4.0 定位为：**物理一致性与资产能力重构版本**，而不是单点加功能。

---

## 1. 接入 Disney BRDF 的调研结论

## 1.1 当前材质系统现状（证据）

1. 材质接口仅有：
   - `emitted(u,v,p)`
   - `scatter(r_in, rec, attenuation, scattered)`
   见 `material.h:17`, `material.h:21`。
2. 现有材质实现为 Lambert/Metal/Dielectric/DiffuseLight/Isotropic，均通过 `scatter` 输出单个下一跳光线。见 `material.h`。
3. 积分器主路径为递归：`attenuation * ray_color(nextRay)`，没有显式 `f * cos / pdf` 权重。见 `camera.h:602-657`，尤其 `camera.h:632`。
4. 当前没有 `BSDF eval`、`pdf`、`light sampling`、`MIS` 的接口与执行路径。可在 `camera.h` 中检索不到相关逻辑。

## 1.2 Disney BRDF 接入可行性分级

### A. “简化接入版”（可做，但不推荐作为终态）

做法：新增 `disney_material`，在 `scatter` 内部混合采样若干 lobe（diffuse/specular/clearcoat），继续复用旧积分器。  

优点：
1. 改动面相对小，能快速看到视觉提升。
2. 可在 1~2 周内做出可运行版本（取决于代码质量与测试）。

缺点：
1. 物理一致性弱，能量控制容易漂移。
2. 高光与复杂光照下噪声明显，收敛慢。
3. 后续演进到高质量路径时会返工。

### B. “正确接入版”（推荐 4.0 主线）

做法：先升级材质/积分器接口，再接 Disney。核心改造：
1. 材质接口拆分为：`sample_bsdf()`、`eval_bsdf()`、`pdf_bsdf()`。
2. 积分器改为显式 throughput 累积：`throughput *= f * cos / pdf`。
3. 新增 NEE（下一事件估计）与 MIS（多重重要性采样）。
4. Disney 参数分层落地：
   - 第一阶段：baseColor, metallic, roughness, specular, clearcoat, sheen
   - 第二阶段：specTint, sheenTint, anisotropic, transmission, thin

结论：**Disney BRDF 在该项目中“可行且值得做”，但必须先完成接口层升级，否则只能得到“看起来像 PBR”的近似版本。**

## 1.3 推荐技术路线（Disney）

1. 先做接口层重构，不立即替换所有材质。
2. 保留旧材质作为兼容层，逐步迁移到 `eval/sample/pdf`。
3. 实现 Disney 基础子集并建立基准场景（塑料/金属/清漆车漆/布料）。
4. 完成 NEE+MIS 后再启用更复杂参数（各向异性、透射等）。

## 2. 外部模型贴图与后续材质支持程度评估

## 2.1 当前“已支持”部分

1. 外部网格导入：已接入 Assimp，支持三角化、法线生成、预变换。见 `model_loader.h:29-37`。
2. 能将外部 mesh 转为内部三角形 hittable，并构建 BVH。见 `model_loader.h:70-165`、`triangle_mesh.h:21-25`。
3. 引擎有图像纹理类 `image_texture`，支持按 `u,v` 采样贴图。见 `texture.h:55-73`。

## 2.2 当前“未打通”关键链路

1. 模型导入阶段未读取并保存外部 UV（`aiMesh->mTextureCoords` 未使用）。
2. 三角形对象仅由几何顶点构造，没有顶点 UV/法线插值数据输入。见 `triangle_mesh.h:15-19`。
3. `triangle` 的 `rec.u/rec.v` 当前是几何重心坐标，不是模型贴图 UV。见 `triangle.h:19-27`。
4. 模型导入接口是“整模型单一材质”传参：`load_model_as_hittable(filepath, mat, opt)`，没有按子网格/材质槽管理。见 `model_loader.h:23-27`。
5. 未接入 MTL/PBR 贴图集（baseColor/normal/roughness/metallic/ao/emissive）。

## 2.3 结论

你现在的系统属于“**外部模型几何已支持，外部模型材质与贴图系统尚未真正支持**”。  
可继续演进，且路线清晰，但需要新增一层“资产与材质绑定系统”，而不是只改 `triangle` 一处。

## 2.4 4.0 对外部资产支持的建议范围

1. 第一阶段（必须）：
   - 支持每三角形插值 UV、法线
   - 支持 baseColor 贴图与 normal map
   - 支持每子网格不同材质
2. 第二阶段（推荐）：
   - 支持 metallic-roughness 纹理
   - 支持 emissive/ao
   - 支持双面材质、alpha cutout
3. 第三阶段（进阶）：
   - 兼容 glTF 2.0 PBR 资产流程
   - 纹理色彩空间管理（sRGB/linear）

## 3. 距离“高拟真 CPU 渲染器”还差多少

## 3.1 当前能力层级判断

当前项目定位：`基础路径追踪器 + 若干高级要素（体积/环境/模型导入）`。  
目标项目定位：`物理一致、资产完备、可稳定生产级画面` 的 CPU 渲染器。

差距判断：**中到大（约 40%~55% 工程完成度）**。  
说明：你已有核心骨架，但缺失的是“决定上限”的关键系统，而不是边缘功能。

## 3.2 关键缺口（按优先级）

1. 积分器物理一致性缺口：
   - 无 `eval/pdf` 接口
   - 无 NEE/MIS
   - 主要依赖纯路径随机命中发光体，复杂场景噪声高
2. 材质系统缺口：
   - 缺少统一 PBR 参数模型（Disney/Principled）
   - 缺少法线贴图、粗糙度金属度贴图驱动
3. 资产系统缺口：
   - 未打通外部模型 UV/多材质槽/贴图集
4. 颜色与成像缺口：
   - 目前以 gamma+clamp 为主，缺少曝光、色调映射、色彩管理流程
5. 收敛与效率缺口（CPU 方向）：
   - 采样策略较基础，缺少自适应采样、路径终止优化、降噪流程
6. 工程验证缺口：
   - 缺少标准化基准场景、误差指标（PSNR/SSIM）与回归机制

## 3.3 达成目标的 4.0 路线建议（CPU优先）

### 阶段 P0（基础重构，2~3 周）

1. 材质接口升级到 `eval/sample/pdf`。
2. 积分器改为迭代 throughput 表达。
3. 增加俄罗斯轮盘终止。

### 阶段 P1（真实感关键，3~4 周）

1. 接入 NEE + MIS。
2. 接入 Disney 基础 BRDF 子集。
3. 建立统一灯光采样接口（面光/环境光）。

### 阶段 P2（资产与贴图，3~4 周）

1. 模型 UV、法线插值、子网格材质槽。
2. baseColor/normal/metallic-roughness/emissive 贴图链路。
3. 导入规则与材质参数校验。

### 阶段 P3（成像与质量稳定，2~3 周）

1. 曝光与色调映射（Filmic/ACES 之一）。
2. 基础降噪接入（CPU 可选 OIDN）。
3. 回归测试与标准场景基准。

总体预计：**10~14 周可到“高拟真 CPU 渲染器”可用版本**（单人主导估计）。

---

## 4. 4.0 版本建议目标定义

建议将 `Ray Tracing 4_0` 的版本目标定义为：

1. 完成 Disney BRDF 的“正确接入版”（非临时 scatter 近似版）。
2. 打通外部模型贴图与多材质支持（至少 baseColor + normal + roughness/metallic）。
3. 完成 NEE+MIS 后，使复杂场景噪声显著下降，达到可稳定产出高拟真静帧。

验收建议：
1. 指定 3 个标准场景（室内、金属粗糙材质、复杂外部模型）
2. 指定同等时间预算下的噪声指标对比（4.0 vs 3_1）
3. 指定材质一致性测试图（球阵列参数扫描）

---

## 5. 结论

你的项目方向正确，基础扎实，具备升级到高拟真 CPU 渲染器的可行性。  
真正的分水岭不在“再加几个材质类”，而在“积分器与材质接口的物理一致性重构 + 资产贴图管线打通”。  
因此 4.0 应优先做架构升级，再做效果堆叠，这样后续无论继续 CPU 深化还是再迁移 CUDA，都会顺畅很多。
